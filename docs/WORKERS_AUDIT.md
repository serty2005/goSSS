# Аудит воркеров и фоновых шлюзов

## 1. Текущее назначение

### `internal/core/gateways/duplicates_gateway.go`
- Периодически сканирует БД по ключевым полям.
- Публикует событие `duplicates.found`.
- Используется как источник сигналов для дальнейшей обработки конфликтов.

### `internal/core/workers/status_actuality_worker.go`
- Периодически проверяет актуальность проблемных статусов оборудования.
- Для кейса `duplicate_found` повторно считает дубликаты и сбрасывает статус при устранении проблемы.
- Обновляет `health_status` и пишет `equipment_status_logs`.

### `internal/core/workers/fr_update_founder.go`
- Периодически сравнивает локальные ФР с данными внешней системы.
- Публикует `discrepancy.fiscal_register.found`.
- Является специализированным источником расхождений ФР.

### `internal/core/gateways/contract_gateway.go`
- Периодически загружает контракты из провайдеров.
- Передает данные в доменный контрактный сервис.
- Уникальная зона ответственности: синхронизация контрактов.

### `internal/core/workers/sd_editor_worker.go`
- Обрабатывает `servicedesk.entity.create.requested` и `servicedesk.entity.update.requested`.
- Выполняет запись во внешние inventory-системы через `IntegrationManager`.

### `internal/services/sd_editor_service.go`
- Легаси-реализация похожего поведения через отдельный сервисный слой.
- В текущем `app` не подключается к запуску.

## 2. Пересечения и дубли

1. `duplicates_gateway` и часть `status_actuality_worker` повторяют проверку дубликатов по одним и тем же полям.
2. `sd_editor_service` дублирует концепцию обработки событий, уже реализованную в `sd_editor_worker`.

## 3. Уникальный и полезный функционал

1. `fr_update_founder` — уникальный механизм обнаружения расхождений ФР.
2. `contract_gateway` — уникальный канал синхронизации контрактов.
3. `status_actuality_worker` — уникальная автоматическая нормализация проблемных статусов и журналирование.

## 4. Целевая схема переработки

1. Выделить общий доменный сервис `DuplicateScanner`.
- Общий интерфейс поиска дубликатов использовать из `duplicates_gateway` и `status_actuality_worker`.
- Убрать дубли SQL/правил сравнения.

2. Зафиксировать `internal/services/sd_editor_service.go` как deprecated.
- Исключить из актуальной архитектурной документации.
- Оставить только `internal/core/workers/sd_editor_worker.go` как рабочий контур.

3. Явно закрепить границы ответственности:
- `duplicates_gateway`: только детект и публикация событий дубликатов.
- `status_actuality_worker`: только проверка актуальности и автоматическое снятие статусов.
- `fr_update_founder`: только сверка ФР и публикация расхождений.
- `contract_gateway`: только синхронизация контрактов.
- `sd_editor_worker`: только исходящая запись изменений в внешние системы.

## 5. Ограничения

- Если внешний источник не присылает событие удаления/изменения в явном виде, система не должна эмулировать его эвристиками.
- Для таких кейсов использовать явную фиксацию ограничения в документации и операционных инструкциях.
