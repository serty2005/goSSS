# 03. HTTP и авторизация

## Общая схема

Router собирается в backend-приложении и разделяет:

- публичные / специальные маршруты;
- защищенные маршруты `/api` с JWT middleware;
- интеграционные webhook endpoints.

## Роли доступа

- `admin` — полный доступ;
- `support_specialist` — операторские операции;
- `intern` — ограниченный доступ в явно разрешенных участках.

## Ключевой инвариант

Проверка прав не должна жить только во frontend. Backend обязан валидировать роль и контекст доступа самостоятельно.

## Legacy-совместимость

`POST /api/submit_json` не переводится на JWT автоматически: это отдельный совместимый контур для getad-агентов с проверкой `X-API-Key`. Важно: если `AGENT_API_KEY` не задан (пустой), backend не отклоняет запросы по ключу и endpoint фактически доступен без `X-API-Key`.

## Webhook создания публикаций

`POST /api/articles/webhook` зарегистрирован до JWT-группы и предназначен для внешних сервисов, которые создают статьи базы знаний без пользовательской сессии.

Авторизация:

- заголовок: `X-API-Key: <ключ>`;
- backend-переменная: `ARTICLE_WEBHOOK_KEY`;
- если `ARTICLE_WEBHOOK_KEY` пустой, handler отклоняет все запросы;
- ключ проверяется только внутри handler этой ручки и не является JWT, agent access token или `AGENT_API_KEY`.

Минимальное тело:

```json
{
  "title": "Заголовок",
  "content": "Markdown-текст"
}
```

Полное тело использует поля обычной статьи: `slug`, `summary`, `content_format`, `type`, `status`, `project_key`, `version`, `tags`, `is_pinned`, `show_on_home`, `links`. Дополнительно доступно `author_name`; если поле пустое, автором записывается `Внешний сервис`.

Правила валидации совпадают с обычным созданием статьи:

- `title` и `content` обязательны;
- `type` по умолчанию `wiki`;
- `status` по умолчанию `draft`;
- `content_format` по умолчанию `markdown`;
- для `release_note` обязательны `project_key` и `version`;
- `links` валидируются по существованию целевой сущности.

Успешный ответ: `201` и стандартный JSON-конверт с DTO статьи.

Ошибки:

- `401` — ключ отсутствует, неверен или `ARTICLE_WEBHOOK_KEY` не задан;
- `400` — некорректный JSON или ошибка валидации payload;
- `500` — публикацию не удалось сохранить.

## Что документировать при добавлении endpoint

1. Маршрут и HTTP-метод.
2. Тип авторизации.
3. Ограничение по ролям.
4. Формат ошибок (русскоязычные сообщения).
5. Изменения в frontend API-клиенте (если есть).
